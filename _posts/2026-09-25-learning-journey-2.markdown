### GROUP PROJECT - Markdown to HTML

## Introduction

This post is a reflection of our group  project in the course Craft  of Computing. In this project,  we had to create a  Bash script to convert  Markdown  files into HTML. It was a difficult but useful  experience for me.

## Why We Created It

The main  purpose of the project was to create a script which can  automatically convert  Markdown files into  HTML instead of doing it  manually.
We also had to handle  different files, layouts and errors, so the script had to work properly in different situations.

## Our Group

Our group members were  **Nithish (it's me🙈),  Joe and Bagavath**. We worked  together on the project and discussed the  problems we faced while creating the script.

## My Experience

At first, I thought  the project was  quite simple  because the main idea was just using Bash and Pandoc. But after starting it, I  realised  that creating the actual script was much harder.
I was involved in writing  and testing the Bash script and checking  whether the Markdown  files were getting converted correctly. I also worked through problems with the  file paths and Pandoc  when the output was not coming as expected.
We  kept testing the script and discussing the problems together.  Sometimes, after  fixing one  problem, another problem would come.

## Challenges

* Bash errors
* Pandoc problems
* File path problems
* Problems while adding the additional features
* Debugging the script again and again

The additional  features made the project  more difficult because we had to make sure  they worked without  affecting the main features.

## Debugging

Debugging was one of the  biggest  parts of our project.
For example,
 when the  Markdown file was not being converted or the output was not coming in the  location we expected, I had  to check the Bash commands, the file paths and the  Pandoc command to find where the  problem was.

We would run the  script, check the error, find where the problem could be and then  try to fix it. After that, we would run it again and  check whether it worked.
Sometimes fixing one problem created another  problem. So we had to repeat this process  many times.

## Additional Features

We also  decided to  complete the  additional features. This made the  project harder because  we had to add them without breaking the features  which were already working.
I was also involved in  testing these features and checking whether  they were  affecting the main script. Even though it took more   time, it helped me  understand the  script better.

## Teamwork and Collaboration

Working with Joe and Bagavath  helped  me understand the importance  of communication in  group projects.
We discussed the problems together and helped each other when someone got stuck. When I found a problem  while testing the script, we discussed it together instead of  trying to solve everything  separately.

## Was It Worth Creating?

I think creating  this  project was worth it.
Even though there were many  frustrating moments, most  of my learning  happened while solving those problems. If everything had  worked  on the first try, I don't think I would have learned as much.

## What I Learned

* Bash scripting
* Pandoc and file conversion
* Debugging
* Handling file paths
* Error handling
* Teamwork and communication
* I also learned that getting errors are a normal part of programming.

## What I Would Improve

If I do  this project again, I would plan the script better before starting.
I would also test each feature separately so that finding errors becomes easier.

## Conclusion

End of the day, this project was difficult but worth it. I learned a lot from  the problems we  faced and from working together as a group.
It gave me a better understanding of how programming works in an actual project.
